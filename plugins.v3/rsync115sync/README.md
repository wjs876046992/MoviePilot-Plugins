# 115 网盘同步与对账重试助手 (Rsync115Sync)

基于 `rsync` + CloudDrive2 (CD2) FUSE 挂载的高可靠 115 网盘媒体同步方案。

> ⚠️ **前置依赖与运行环境要求**：
> 1. 本插件**强依赖 CloudDrive2 (CD2)** 将 115 网盘挂载到本地宿主机（如 `/volume2/CloudNAS/115`）；
> 2. 若 MoviePilot 运行在 Docker 容器中，**必须将宿主机上的 CD2 挂载路径及本地源媒体目录完整映射入 MoviePilot 容器中**（挂载模式建议开启 Slave 共享/读写）；
> 3. 运行环境（宿主机或容器内）需支持 `rsync` 命令（通常终端执行 `apt update && apt install -y rsync` 即可）。

### 核心特性
1. **入库冷却延迟（Cool-down Buffer）**：支持配置入库 N 小时后再同步（默认 2.0 小时，可设 0 禁用），留足自动外挂字幕下载与媒体服务器刮削时间，杜绝漏下字幕。
2. **CD2 挂载优化**：严格继承 `sync_115.sh` 黄金参数 `--size-only`，解决云盘不支持毫秒级精确 mtime 导致的全量重传问题。
   为兼容 115 秒传机制，**刻意不使用 `--inplace` / `--partial`**（断流文件无法触发秒传），
   因此中断时可能在目标端留下临时文件（形如 `影片.mkv..xrp4gj`）。
   注意默认排除规则里的 `..*` **只能匹配以 `..` 开头的名字**，挡不住这种 `..`
   出现在中间的主流形态；若要挡住应改成 `*..*`（依据 rsync 通配实测行为）。
   且排除规则只作用于源端，**无法清理目标端已有的残留**，需手动删除，
   详见 [USAGE.md](./USAGE.md) 的常见问题。
3. **双向完整性对账（解决彻底缺失）**：同步后比对源与目标大小，自动捕获未传或断流残缺文件并加入重试队列。
4. **存量媒体补传**：针对启用插件前已入库的历史媒体，支持一键扫描本地存量并分批补传。
   补传以「媒体文件 + 同主名伴生字幕」为单位，全程只读源端目录（零 115 API 开销），
   实际传输走定向清单，不遍历 115 挂载点。受单批上限与限流配额约束，未完成部分自动续跑。
5. **全功能移动交互指令**：
   - `/rsync_status`：查看当前同步状态、冷却中文件数与待重试清单。
   - `/rsync_retry`：自动清理目标端半截坏文件，并只对缺失/残缺文件进行精准重试。
   - `/rsync_sync`：手动触发已达到冷却时间的入库媒体同步。
   - `/rsync_force`：忽略冷却时间限制，对全部映射执行一次全量校验（API 开销大，见下方说明）。
   - `/rsync_search <关键字>`：在本地入库文件中查找并生成候选重试清单。
   - `/rsync_confirm [序号|all]`：确认执行上一步查找到的文件（支持 `1`、`1,2`、`1-2 4`、`all`）。
   - `/rsync_ignore <规则>`：忽略指定文件不再报警（支持 `list` / `clear`）。
   - `/rsync_backfill`：扫描并补传存量媒体（含同名字幕），分批自动推进。
   - `/rsync_backfill_clear`：清空存量补传队列。

> ⚠️ **关于 `/rsync_force` 与 API 开销**：该命令会遍历 115 挂载点全目录做校验，
> 请求量按媒体库文件数计，可能上万次。请勿频繁执行，日常同步请使用 `/rsync_sync` 或等待定时巡检。
> 存量补传请优先用 `/rsync_backfill`，它只扫描源端、按配额分批推进，风控风险低得多。
